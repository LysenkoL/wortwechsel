# Журнал решений

Формат: номер, решение, почему, что отвергли. Новые решения добавляются
в конец. Решение, предложенное исполнителем (GPT/Codex) без согласования,
помечается **ПРЕДЛОЖЕНО (GPT)** и ждёт подтверждения Claude.

---

**D-001. Своё интервальное повторение вместо Quizlet.**
Почему: у Quizlet нет открытого API (старый API 2.0 закрыт для всех, кроме
партнёров), а главное — Quizlet тренирует «слово → перевод», то есть
узнавание. Нам нужно употребление в собственной фразе.
Отвергли: автоматическую загрузку в Quizlet; Anki через AnkiConnect (работает
только при включённом Anki на ПК). Экспорт TSV для Quizlet/Anki — фаза 2.

**D-002. PWA на React + TypeScript + Vite.**
Почему: один код для телефона и ПК, устанавливается на экран телефона,
стек уже знаком (сайт шахматной федерации — тоже React/Vite).
Отвергли: нативное приложение (дольше, нужны сторы).

**D-003. Данные только на устройстве (IndexedDB через Dexie).**
Почему: одна пользовательница, не нужен сервер с базой, ноль затрат,
приватность. Перенос между устройствами — экспорт/импорт JSON.
Риск: очистка данных браузера. Митигируем напоминанием о резервной копии
раз в неделю (T07).

**D-004. ~~Сервер — только тонкий прокси на Vercel Functions.~~ ЗАМЕНЕНО → D-014, D-016.**
Почему: ключ API нельзя держать в браузере. Vercel даёт фронтенд и функции
в одном деплое, бесплатный тариф для личных проектов.
Отвергли: Cloudflare Workers (чуть сложнее для старта), свой сервер.

**D-005. ~~Один провайдер AI — OpenAI — для распознавания и анализа.~~ ЗАМЕНЕНО → D-015, D-017.**
Почему: один ключ, один счёт, одна точка лимитов. Названия моделей
в переменных окружения, чтобы менять без правки кода. Доступ к модели
изолирован в `api/_lib/openai.ts` — позже можно заменить провайдера
для анализа, не трогая остальной код.
Важно: подписка ChatGPT Plus **не** включает API, API оплачивается отдельно.

**D-006. Оценку для FSRS ставит код, а не модель.**
Почему: модель хорошо определяет факты («употребила / правильно / смысл
сохранён»), но нестабильно ставит баллы. Правило в `src/srs/rating.ts`
можно протестировать и поменять одним местом.

**D-007. Одна карточка FSRS = одна сохранённая замена, но задание = фраза.**
Почему: расписание считается для каждого выражения отдельно, а показывать
удобнее целую фразу, где проверяются все её «созревшие» замены.

**D-008. Распознанный текст можно поправить до анализа.**
Почему: модели распознавания часто «причёсывают» речь неносителя —
исправляют ошибки, которых не было в тексте. Последнее слово за Леной.
(`prompts/transcribe-hint.txt` в фазе 1 не используется — он пригодится,
если в фазе 2 добавим распознавание через Gemini, см. D-017.)

**D-009. Максимум 3 замены на фразу и явный список «оставь как есть».**
Почему: больше трёх — перегруз, ничего не запоминается. Модели склонны
заменять всё подряд на «красивые» слова, поэтому в схеме есть поле `keep`,
где модель обязана объяснить, почему простое слово здесь лучше.

**D-010. Промпты и JSON-схемы — отдельные файлы и единственный источник истины.**
Почему: это ядро продукта. Код получает их через генерацию
(`npm run sync`), поэтому промпт можно улучшать, не трогая код,
а исполнитель не может случайно «подкрутить» его в коде.

**D-011. Строгие JSON-схемы без `minItems`/`maxItems`/`maxLength`.**
Почему: в строгом режиме Structured Outputs поддерживается не каждое
ключевое слово. Ограничения количества описаны в промпте и
дополнительно применяются в коде (обрезка массивов).

**D-012. Слабые слова считаются с первого дня.**
Почему: статистика (фаза 2) нужна «до/после». Поле `generic_words` уже
в ответе анализа фазы 1, данные копятся в `utterances.analysis`.

**D-013. Аудио не хранится.**
Почему: для обучения нужен только текст; аудио быстро забивает IndexedDB
на телефоне.

## 2026-10-25 — переход на бесплатный стек

Причина: у Лены подписка ChatGPT Plus, а API OpenAI оплачивается отдельно.
Цель — запуск без платных сервисов.

**D-014. Хостинг — GitHub Pages, своего сервера нет.**
Почему: Лена уже публикует проекты на GitHub Pages; бесплатно; нечего
обслуживать. Следствия: ключ API живёт на устройстве (D-016); на бесплатном
тарифе GitHub Pages работает только для публичных репозиториев — поэтому
в репозитории не должно быть личных данных (фразы фазы 0 — в `.gitignore`).
Маршрутизация — `HashRouter`, чтобы прямые ссылки не давали 404.
Отвергли: Vercel/Cloudflare-прокси (лишний сервис ради одного ключа).

**D-015. AI — Gemini API на бесплатном тарифе.**
Почему: бесплатный тариф без банковской карты; структурированный вывод по
JSON-схеме. Анализ фраз — модель Flash (качество важнее, но бесплатный
дневной лимит у неё маленький — по отзывам разработчиков около 20 запросов
в день), проверка ответов — Flash-Lite (лимит в разы больше). Google не
публикует точные лимиты — они видны в AI Studio в проекте. Модели
меняются в настройках без правки кода.
Цена решения: на бесплатном тарифе Google может использовать тексты
запросов для улучшения своих продуктов — в приложении подсказка «без
личных данных». Если бесплатных лимитов не хватит: предоплата в Google
(от 5 $) или другой провайдер — доступ к модели изолирован в `src/ai/gemini.ts`.
Отвергли: OpenAI API (платный); локальные модели в браузере (тяжело для
телефона, слабый немецкий); ручное копирование в ChatGPT (неудобно каждый день).

**D-016. Ключ API вводит Лена в настройках, хранится только на устройстве.**
Почему: без сервера ключ неизбежно в браузере. Это допустимо, потому что
пользователь один и ключ его собственный. Защита: ключ не попадает в код,
репозиторий и логи; в Google Cloud Console ключ ограничен сайтом
`<логин>.github.io` и одним API — утёкший ключ бесполезен на чужом сайте.
Для скрипта фазы 0 — отдельный ключ в `.env.local`.

**D-017. Распознавание речи — Web Speech API браузера.**
Почему: бесплатно, не тратит лимиты Gemini, текст появляется прямо во время
речи. Риски: на iPhone в режиме установленного приложения распознавание
может не работать — проверяем в T08, запасной путь — открыть в Safari;
браузер тоже «причёсывает» речь — поэтому шаг правки текста остаётся (D-008).
Фаза 2 (по необходимости): распознавание через Gemini по аудио.

**D-018. В JSON-схемах нет `null`.**
Почему: разные провайдеры по-разному поддерживают `type: [..., "null"]`.
`corrected_sentence` теперь строка, пустая — если ошибок нет.

**D-019. Сначала локально, до идеала; публикация — в самом конце.**
Почему: Лена хочет довести приложение до ума у себя, как в прошлых
проектах, и только потом выкладывать. Следствия: нет удалённого
репозитория и `git push` до T08; передача работы между агентами — через
саму папку на ПК и локальные коммиты; проверка на телефоне — по Wi-Fi
через `npm run dev:phone` с самоподписанным HTTPS (микрофону нужен HTTPS).
Целевая публикация (GitHub Pages, D-014) не меняется — просто откладывается.

**D-020. Публикация разрешена Леной (2026-10-25).**
Лена посмотрела локальную версию, написала «можем забросить на GitHub» и будет
тестировать на телефоне, сообщая правки. D-019 снят для T08; остальное
(ключ только на устройстве, репозиторий без личных данных) действует.

## 2026-10-26 — модуль «Слова» (T14)

**D-021. Наборы слов «как Quizlet» — отдельная вкладка рядом с ядром.**
Почему: Лена попросила нормальное изучение слов с группировкой по темам и
разными тренировками. В видении карточки «слово → перевод» стояли в «не
делаем», потому что тренируют узнавание, а не речь. Компромисс: ядро (своя
речь → замены → «скажи иначе») не меняется; наборы — дополнительный
инструмент, но настроенный на активный словарь: направление по умолчанию
рус → нем, письмо и говорение по-немецки, связки вместо голых слов
(в готовых наборах и в промпте `cards.md`). Тема набора — те же 4 сферы
(`Context`), чтобы не плодить второй классификатор. Сохранённые выражения
можно скопировать в набор.

**D-022. Два вида прогресса: «освоение» и FSRS.**
Почему: Quizlet-режимы (выбор, подбор, тест) дают много лёгких ответов —
если каждый двигал бы FSRS, интервалы «раздувались» бы за один вечер.
Поэтому все режимы пишут только `stats` (полоска «не изучено / учу / знаю»),
а расписание двигает только «Повторение» с честной самооценкой.

**D-023. Ответы в тренировках проверяются локально, без AI.**
Почему: тренировки должны работать офлайн и не тратить бесплатный лимит
Gemini (он нужен анализу фраз). Допуски (регистр, умлауты, 1–2 опечатки)
снимают «ложные ошибки», артикль проверяется строго — это и есть то, что
нужно выучить. Спорные случаи закрывает кнопка «Я была права».

**D-024. AI в наборах — только для наполнения.**
Подбор слов на тему и «Дополнить» (перевод/пример к её словам) — одна схема
`cards.schema.json`, модель анализа, свой счётчик `generate`. AI не
проверяет ответы в тренировках (D-023).

**D-025. Резервная копия version 2, Dexie version 2 — только добавление.**
Старые копии (version 1) импортируются; новых полей в старых таблицах нет,
кроме необязательного `UsageDay.generate`.

**D-026. Картинки к словам — эмодзи-ассоциации, не фото.**
Почему: Лена попросила ассоциативные картинки. Эмодзи бесплатны, работают
офлайн, ничего не весят в IndexedDB и подходят к абстрактным связкам
(`✋📄` Widerspruch einlegen), для которых фото не найти. AI ставит 1–2 эмодзи
вместе с переводом; у готовых наборов они в `data/starter-decks.json`
(у уже добавленных наборов дописываются при запуске); у старых карточек их
добавляет «Дополнить». Отвергли пока: фото из Wikimedia/Openverse (сеть,
слабое качество для абстрактного) и генерацию картинок (нет бесплатного лимита).
