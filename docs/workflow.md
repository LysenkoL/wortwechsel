# Как работать: Claude + GPT

## Главное правило: сначала локально, до идеала

Всё делается и проверяется **на компьютере Лены**, в папке
`C:\Users\elenk\wortwechsel`. В интернет (GitHub, GitHub Pages) ничего не
выкладывается, пока Лена сама не скажет: «приложение готово, публикуем».
Публикация — последний тикет T08, и он не начинается без этого слова.

- Приложение запускается локально: `npm run dev` → открыть в Chrome на ПК.
- Проверка на телефоне — тоже локально, через домашний Wi-Fi
  (`npm run dev:phone`, см. T01), без выкладки в интернет.
- Ключ Gemini — в `.env.local` (для скрипта) и в настройках приложения.

## Кто что делает

| Задача | Кто |
|---|---|
| Что строим, порядок, приоритеты, «готово к публикации» | Лена |
| Архитектура, промпты, схемы, тикеты | Claude |
| Код по тикетам | GPT/Codex или Claude — у кого сейчас есть лимит |
| Проверка готового тикета | Claude |
| Проверка в браузере и на телефоне | Лена |

Единый источник правды — **файлы в этой папке**, а не история чатов.
Поэтому переключаться между агентами можно в любой момент: всё нужное
лежит в `STATUS.md` и `tasks/`.

## Эстафета по лимитам

**Эстафетная палочка — сама папка `C:\Users\elenk\wortwechsel`.**
Оба агента работают в ней напрямую: Codex — как обычно, Claude — через
подключённую папку (Cowork). Работает тот, у кого сейчас есть лимит.

1. **Начало:** прочитать `STATUS.md` → взять тикет.
2. **Во время работы:** после каждого законченного шага — локальный
   коммит git (без `push`, удалённого репозитория пока нет).
3. **Конец или лимит на исходе:** заполнить «Передачу смены» в `STATUS.md`
   → коммит.
4. Агент оборвался без передачи смены → следующий начинает с
   `git status` и `git diff` (фраза ниже).

Claude не может запускать `npm` и `git` на компьютере Лены. Поэтому:
- Claude пишет и правит файлы, а проверку (`npm install`, `npm test`,
  `npm run dev`) запускает Лена или Codex;
- коммиты после работы Claude делает Codex или Лена — это первая строка
  в фразе «Начать работу» ниже.

Кому что лучше отдавать, если лимит есть у обоих:
- **Claude:** промпты и схемы, ревью, T02 (логика повторения), T03 (AI-слой).
- **Codex/GPT:** T00, T01 (каркас), T04, T05–T07 (экраны), запуск тестов.

Если Claude долго недоступен, Codex берёт следующие тикеты, а готовые
копятся в статусе `review` — Claude проверит их пачкой.

## Обычный цикл

```
Claude пишет/уточняет тикет
        ↓
GPT/Codex (или Claude) реализует → тесты → коммит → тикет в «review»
        ↓
Claude проверяет → «done» или замечания
        ↓
Лена смотрит в браузере на ПК и на телефоне
        ↓
… все тикеты T00–T07 готовы и Лене всё нравится
        ↓
Лена: «публикуем» → T08 (GitHub + GitHub Pages)
```

## Готовые фразы для копирования

**Начать работу с GPT/Codex** (открыть папку `wortwechsel` в Codex):
> Прочитай AGENTS.md и STATUS.md. Если есть незакоммиченные изменения от
> Claude — сначала проверь их (npm test) и закоммить. Потом возьми
> следующий тикет со статусом todo, у которого выполнены зависимости, и
> реализуй его по спецификации. В конце — передача смены и коммит.

**Начать работу с Claude** (в этом чате или новом чате Cowork):
> Работаем над проектом в папке C:\Users\elenk\wortwechsel. Прочитай
> CLAUDE.md и STATUS.md и продолжай с того, что там следующее.

**Продолжить прерванное:**
> Прочитай STATUS.md, блок «Передача смены», и продолжи с того места,
> где остановился предыдущий агент.

**Перед тем как закончить сессию** (или если лимиты вот-вот кончатся):
> Обнови STATUS.md — блок «Передача смены» — по правилам из AGENTS.md
> и сделай коммит.

**Отдать на проверку Claude:**
> Проверь тикет T0X: посмотри изменения и STATUS.md, по чек-листу из CLAUDE.md.

**Предыдущий агент оборвался без передачи смены:**
> Предыдущий агент прервался без передачи смены. Посмотри git status,
> git diff и последний коммит, сравни с тикетом, допиши «Передачу смены»
> в STATUS.md и продолжай.

**GPT упёрся в вопрос:**
> Запиши вопрос в STATUS.md → «Вопросы к Claude» и остановись.
Потом принеси вопрос Claude.

## Когда обязательно идти к Claude
- После каждого тикета — проверка.
- Когда в `STATUS.md` появился вопрос к Claude.
- Перед переходом к следующей фазе.
- Если хочется поменять промпт, схему, архитектуру или добавить функцию.
- Если анализ фраз в приложении начал давать странные замены.

## Почему так
- Промпты и схемы — ядро продукта. Если исполнитель будет
  «подкручивать» их по ходу, качество поплывёт незаметно. Поэтому они
  защищены, а в код попадают только через `npm run sync`.
- Маленькие тикеты с чётким «Готово, когда» — так любой агент может
  подхватить работу без истории переписки.
- Коммит после каждого шага — переключение между агентами ничего не ломает.
- Публикация в конце — пока приложение не доведено до ума, в интернете
  ему делать нечего.
